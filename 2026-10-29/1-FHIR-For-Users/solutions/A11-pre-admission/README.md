# A11 Patient-facing pre-admission form: full solution

**Status: verified.** Every FHIRPath expression was checked with fhirpath.js. The full loop ran in the patched Smart
Forms playground against Meld (headless, 28 Oct 2026): the patient's form was pre-populated and filled in, its
QuestionnaireResponse was stored, and the nurse-side form then pre-populated from it.

## What it does

**`A11-pre-admission.json`** is the patient's form. Id `soln-A11-pre-admission`, canonical
`https://aehrc.github.io/qh-connectathon/track1/solutions/Questionnaire/A11-pre-admission`, 0.2.0. It has `patient` launch context.

| Section | Content |
|---|---|
| About you | Pre-populated from the Patient for the patient to check: name, date of birth, sex, Medicare number, phone (mobile first), home address, preferred language, interpreter (AU Base `interpreter-required`) |
| Your health | Told you have anaemia / low iron; iron tablets; iron drip (when? reaction?); tiredness; bruising; gut bleeding; heavy periods (shown only if sex = female); blood thinners (which?); kidney problems |
| Food and diet | How you eat (SNOMED: normal / pescatarian / vegetarian / vegan diet); red meat frequency (only for meat eaters); tea or coffee with meals; appetite or weight loss; foods you can't eat |
| Blood transfusion | Transfused before (reaction?); **would you accept a transfusion?** (required: yes / only some products / no / not sure); which products (SNOMED: red cells, platelets, plasma, cryoprecipitate, albumin, cell salvage); why (optional); Advance Health Directive; want to talk to the nurse |
| Finishing up | Who filled in the form |

The questions are in plain language, mostly Yes / No / Not sure (`v2-0136` Y/N + `data-absent-reason` `asked-unknown`).
Its write-back is the **QuestionnaireResponse itself**. There is no template extraction. linkIds are `pam-pa-…`,
under the top-level group `pam-pre-admission`.

**`A11-nurse-import.json`** is the nurse-side module that reads it. Id `soln-A11-nurse-import`, canonical
`…/solutions/Questionnaire/pam-patient-reported`, 0.2.0, `assemble-child`, group `pam-patient-reported`. It has a
standalone copy, `A11-nurse-standalone.json` (`soln-A11-nurse-standalone`).

```text
x-fhir-query  paResponse = QuestionnaireResponse?subject=Patient/{{%patient.id}}&status=completed&_sort=-authored&_count=50
latest A11    %paResponse.entry.resource.where(questionnaire.startsWith('https://aehrc.github.io/qh-connectathon/track1/solutions/Questionnaire/A11-pre-admission')).first()
an item       <latest A11>.repeat(item).where(linkId = 'pam-pa-transfusion-accept').answer.value
```

It fills: date and id of the patient's form; would accept a transfusion; accepted products (repeating
Codings); Advance Health Directive; previous transfusion reaction; previous iron infusion; blood thinners
(`'Yes: ' + names`); diet; wants to talk to the nurse. If the patient has no response yet, a note
says so (`enableWhen … exists = false`).

The nurse items use the same answer codes as the patient form, so the Codings carry over unchanged. To put this into
an existing PAM module (for example, a "limited consent / refuses blood products" item in A6 that feeds the Flag), copy
the `paResponse` variable onto that module's group and give the item an `initialExpression` like the one above.

**Why the query doesn't use `questionnaire=`.** Smart Forms stores `QuestionnaireResponse.questionnaire` as
`<url>|<version>`. Meld matches `questionnaire=` only on that exact string: `questionnaire=<url>` gives 0 results,
and `questionnaire=<url>%7C0.2.0` gives 1. Both were tested and are in `verify.mjs`. So the query filters on subject and status,
and the FHIRPath picks the A11 responses whatever their version. If you pin a version,
`&questionnaire=<url>|0.2.0` works too.

## Try it

1. Load the test data (one line):
   `curl -X POST -H 'Content-Type: application/fhir+json' --data-binary @test-data.json https://gw.interop.community/QHConnectathon2026/open`
2. Playground: https://aehrc.github.io/qh-connectathon/smart-forms/, then **GO TO PLAYGROUND**, then the gear icon. Set the source server to the Meld open
   endpoint (validate, then save), choose patient **Grace Preadmit-A11**, and click SAVE.
3. Pick **soln-A11-pre-admission**, click **BUILD FORM**, then **POPULATE → Pre-populate**. The demographics fill in. Answer the questions;
   *Only some blood products* shows the product checklist.
4. Pick **soln-A11-nurse-standalone**, click **BUILD FORM**, then **POPULATE → Pre-populate**. The items fill from `soln-A11-qr-1`.
5. Clean up: `./delete-test-data.sh`.

The playground can't save a QuestionnaireResponse to the server. In real use the patient's form is opened with
a SMART launch in the Smart Forms app, which saves the response (*Save as final*) to the FHIR server. `playground.mjs`
stores it with a PUT instead.

## Verification

* `node solutions/A11-pre-admission/verify.mjs` (from `T/`, test data loaded) gives **31 checks passed**. With `--offline`
  (uses `test-data.json`, no server) it gives **30 checks passed**. The checks cover: structure; every `enableWhen` targets an existing
  question and answer; the nurse module reads only existing A11 linkIds, with identical answer options; every
  initialExpression of both forms (including a sparse Patient); and the nurse query on Meld. Edge cases: a newer response to another form is ignored,
  the latest A11 response wins over an older one, and there is no response at all.
* Playground (`node solutions/A11-pre-admission/playground.mjs`, 28 Oct): the demographics pre-populated
  (`img/patient-1-prepopulated.png`). The enableWhen branches worked: heavy periods for a female patient; products, reason and directive for
  *only some* (`img/patient-2-transfusion.png`). The response was stored on Meld. The nurse form pre-populated:
  *Only some blood products*, Albumin + Cell salvage, directive Yes, no previous iron infusion,
  "Yes: Aspirin 100 mg daily", vegetarian, wants to talk (`img/nurse-1-prepopulated.png`).

## Known gaps and decisions

* The transfusion preference, red-meat frequency, reason and "completed by" answers use placeholder local CodeSystems
  (`https://aehrc.github.io/qh-connectathon/track1/CodeSystem/…`), like the synthetic data. Products and diets
  use SNOMED CT-AU codes (active on Ontoserver, 28 Oct). The product answers are SNOMED *procedure* concepts
  (e.g. 116863004 *Transfusion of red blood cells*, with plain-language displays). SNOMED CT-AU does have active
  refusal concepts (699128009 *Blood transfusion declined*, 699054003 *Administration of blood product declined*,
  708129006 *… refused for religious reason*; A6 uses the last two), but none for "only some products", hence the
  local transfusion-preference codes. (Corrected in review, 29 Oct.)
* Corrections the patient makes to demographics stay in the response. Nothing writes them back to the Patient.
* The patient's wishes are not turned into a Flag or Consent here; that is the nurse's decision (A6). The nurse module only
  pre-populates.
* The Questionnaire isn't split into pages for mobile. Smart Forms renders groups as cards.
